# pepper_bot

Парсер свежих сделок и промокодов pepper.ru с автопостингом готовых карточек
в Telegram-канал и ботом для поиска промокодов за 3 / 12 / 24 часа.
Работает чисто на HTTP-запросах, без браузера: ycch-антибот Яндекса проходится
решением proof-of-work (sha256, ~10 бит — миллисекунды), TLS-отпечаток
имитируется через `curl_cffi`.

## Формат карточек

Посты оформляются в стиле «🐾 Кот нашёл скидку» / «🐾 Кот нашёл промокод»:
название, цена и экономия (если обе цены найдены), условия из описания,
код и ссылка на товар/активацию (без ссылки на страницу Pepper). В карточке
текст «Ссылка на товар» кликабелен, плюс добавляется inline-кнопка перехода.
Срок добавляется только если сайт явно отдаёт дату окончания.
Оговорки о регионе, онлайн-оплате и остатках добавляются только при наличии
соответствующего текста на странице.

Оценка и короткий вердикт сейчас формируются простыми правилами по наличию
промокода/размеру скидки; это шаблонная эвристика, а не редакционная оценка.

## Режимы публикации и админ-панель

- `PEPPER_PUBLISH_MODE=auto` — публиковать сразу в канал.
- `PEPPER_PUBLISH_MODE=review` — присылать карточку администратору; доступны
  «Принять и опубликовать», «Пропустить», «Редактировать».
- Inline-панель `/start` → режим публикации переключается кнопками.
- `PEPPER_TG_ADMIN_IDS` — allowlist Telegram user ID через запятую. Все
  команды и callback-кнопки проверяют ID пользователя.
- `PEPPER_TG_ADMIN` — chat ID админа, куда отправлять карточки в review-режиме.
- `/stats` показывает найдено/опубликовано/пропущено/ожидает/ошибки за 3 ч,
  12 ч, 24 ч и 7 дней. `/errors` показывает последние ошибки, `/pending` —
  очередь модерации.
- `/whoami` сообщает Telegram ID для настройки allowlist.
- При старом `pepper_seen.sqlite3` поля очереди и статистики добавляются
  автоматически при старте.

### Inline-панель

После `/start` управление идёт через inline-меню: скан промокодов за 3/12/24
часа, статистика, ошибки, очередь модерации, режим публикации и канал.
В каждом подменю есть кнопка «⬅️ Назад». Канал можно сменить через «📣 Канал»;
бот проверяет его через `getChat`, после чего новые карточки публикуются туда.

Кнопка периода запускает живой скан сайта, а не выборку SQLite: парсер
проходит страницы `/new` и `/deals`, открывает карточки, сравнивает
`Article.datePublished` с выбранным окном и отправляет найденные скидки и
промокоды администратору с прогрессом `проверено/найдено`. Такие результаты
не заливаются автоматически в канал.

Фото товара скачивается с Pepper и отправляется в `sendPhoto`; если Telegram
уже выдавал `file_id`, review-карточка повторно использует его после перезапуска.

Редактирование в review-режиме: нажать «Редактировать» и отправить одной
строкой `название | цена | старая цена | промокод | URL товара | описание`.

## Что собирает карточка (по подсказке)

1. **Фото товара** — `og:image` / JSON-LD, прикладывается к посту (sendPhoto).
2. **Название** — JSON-LD `Article.headline`.
3. **Цена было-стало** — JSON-LD `Product.offers.price` + старая цена из ленты.
4. **Промокод** — точный виджет копирования в DOM (span с кодом перед
   `/visit/deals`), фолбэк — эвристика из текста описания.
5. **Подробнее о скидке** — чистое тело `div.content-formatting` (блок
   «Подробнее о скидке» на странице).

Плюсом: температура (🔥/⭐/🌡), число комментариев, бренд, срок действия,
ссылка на сделку.

## Установка

```bash
cd pepper_bot
python3 -m venv .venv
source .venv/bin/activate        # windows: .venv\Scripts\activate
pip install curl_cffi selectolax
cp .env.example .env             # токен бота, chat_id канала, chat_id админа
```

## Настройка (.env)

| Переменная             | По умолчанию         | Что делает                                  |
|------------------------|----------------------|---------------------------------------------|
| `PEPPER_TG_TOKEN`      | —                    | токен бота от @BotFather                    |
| `PEPPER_TG_CHAT`       | —                    | `@имя_канала` или числовой `-100...`        |
| `PEPPER_TG_ADMIN`      | —                    | chat_id для демо/диагностики                |
| `PEPPER_TG_ADMIN_IDS`  | —                    | user ID администраторов (через запятую)     |
| `PEPPER_INTERVAL`      | `180`                | пауза между циклами парсинга, сек           |
| `PEPPER_MAX_PER_CYCLE` | `5`                  | лимит постов за цикл (антифлуд)             |
| `PEPPER_SEED_FIRST`    | `true`               | первый запуск помечает текущее прочитанным  |
| `PEPPER_DB_PATH`       | `pepper_seen.sqlite3`| файл базы (посты + каталог промокодов)      |
| `PEPPER_REQUEST_DELAY` | `2.0`                | пауза между HTTP-запросами, сек             |
| `PEPPER_PROXY`         | —                    | HTTP/HTTPS прокси (optional)                |
| `PEPPER_TG_PROXY`      | —                    | прокси для Telegram API (нужен, если Telegram недоступен с сервера) |
| `PEPPER_2CAPTCHA_KEY`  | —                    | API ключ 2captcha для обхода Yandex капчи   |

### Обход Yandex SmartCaptcha

Если pepper.ru требует капчу (датацентр IP, прокси), добавь `PEPPER_2CAPTCHA_KEY`:

1. Зарегистрируйся на https://2captcha.com
2. Пополни баланс (~$3 за 1000 капч)
3. Скопируй API ключ из личного кабинета в `.env`:
   ```
   PEPPER_2CAPTCHA_KEY=ваш_ключ_здесь
   ```

Бот автоматически отправит капчу на решение через 2captcha API и продолжит работу.

Бота добавить в канал администратором с правом публикации.

## Запуск

```bash
python main.py               # вечный цикл: парсинг -> канал + бот-поиск
python main.py --once        # один проход парсинга
python main.py --once --dry  # карточки в stdout, ничего не слать
python main.py --seed        # пометить текущие сделки прочитанными и выйти
python main.py --bot         # только бот с поиском промокодов
python main.py --demo        # тестовая карточка-подсказка в TG_ADMIN
```

## Бот: поиск промокодов

В боте: `/start` -> «Скан промокодов» -> период **3 / 12 / 24 часа**.
Каждый выбор запускает живой обход лент Pepper и страниц сделок, проверяет
`Article.datePublished` относительно текущего времени и присылает админу
найденные скидки/промокоды в виде карточек с фотографиями и ссылкой на товар.
Результат такого скана не публикуется в канал и не зависит от локального
каталога; он предназначен для проверки работы парсера.

`--demo` шлёт в TG_ADMIN медиагруппу из скриншотов подсказки
(`demo_photos/*.jpg|png`) с подписью-карточкой и инлайн-кнопками
«🃏 Показать карточку» / «📄 Показать данные».

## Как это работает

1. `GET /deals` и `/new`. Если пришла «Верификация» — из
   `window.__SSR_DATA__` берутся `action`, `pow.prefix`, `pow.complexity`,
    брутфорсится nonce, `POST {pow: nonce}` на `action` — сессия получает
    cookies, дальше обычные GET идут напрямую. Если вместо PoW приходит
    отдельная SmartCaptcha с `sitekey`, используется 2captcha API v2.
2. Карточки лент — `article.deal-card`: ID из URL, заголовок, температура,
   цены, картинка.
3. Новые ID -> страница сделки: JSON-LD (`Article`/`Product`/`WebPage`),
   промокод из DOM-виджета, тело из `div.content-formatting`, комментарии.
4. Рендер -> sendPhoto в канал. Промокод -> каталог SQLite для бота.
   Ретраи неудачных до 5 попыток, seed первого запуска, идемпотентность.

## Хрупкие места

- Вёрстка (`article.deal-card`, `div.content-formatting`, виджет кода)
  может поменяться — правится в `pepper_client.py` (`_parse_card`,
  `_CODE_DOM_RE`, `get_deal`).
- При агрессивной частоте опроса антибот может поднять сложность PoW —
  код берёт сложность из ответа, но интервал лучше держать от 120 секунд.
